## §1 现成解：低置信自动换图重试（**已完成，可直接用**）

### 1.1 做了什么

把 220 张实测得出的最优策略从"报告结论"变成"脚本行为"：

| 项目 | 改动前 | 改动后 | 依据 |
|---|---|---|---|
| 低置信阈值 | `0.60` | **`0.999`** | 实测最优：自动化 84.5% + 自动部分 100% 正确 |
| 换图重试 | 无 | **最多 3 次** | 新增 |
| 换图控件定位 | 无 | 9 个候选选择器兜底 | 抗页面改版 |
| 状态提示 | "置信度偏低" | 显示重试进度 + 最终结果 | 可观测 |
| 版本 | 油猴 4.4.5 / 扩展 1.0.4 | **油猴 4.5.0 / 扩展 1.0.5** | — |

**关键发现**：改动前的 `lowConfidence: 0.60` 是个**从未生效的死阈值** —— 实测中 5 个错误样本的最低置信都在 **84.39%~99.58%**，永远够不到 0.60。这个功能此前形同虚设。

### 1.2 实现要点

**换图控件定位**（油猴 `findRefreshButton` / 扩展同名函数）：

```js
refreshSelectors: [
    '.captcha-refresh', '#captcha-refresh',
    '.captcha img + a', '#captcha-img + a', '#captcha-img + span',
    'img[id*="captcha" i] + a', 'img[id*="captcha" i] + span',
    'a[onclick*="captcha" i]', 'button[onclick*="captcha" i]'
]
```

不用固定 id —— jAccount 的刷新控件改版过多次，写死会在改版后**静默失效**（表现是"低置信却从不换图"且无报错）。改为按候选列表依次试，并要求元素可见（`offsetWidth/Height > 0`）。

**重试循环**（严格约束，避免无限换图）：

```
识别 → 置信 < 0.999 且 长度为 4/5
     → 点换图 → 等新图就绪（decode() 优先，1200ms 兜底）
     → 重新识别 → 记录置信最高的那次
     → 最多循环 3 次
最终仍低置信 → 采用置信最高的结果 + 橙色标注 + 提示用户核对
```

**已覆盖的边界情况**（8 项行为测试全通过）：

| # | 场景 | 期望 | 结果 |
|---|---|---|---|
| 1 | 首次就高置信 | 不换图 | ✓ |
| 2 | 低置信→换图 2 次命中 | 采用第 3 次 | ✓ |
| 3 | 持续低置信 | 换满 3 次后用**最高置信**那次 | ✓ |
| 4 | 找不到换图控件 | 立即停止，不空转 | ✓ |
| 5 | 重试得到长度异常 | 保留上次结果 | ✓ |
| 6 | 5 位码同样触发 | 换图 1 次命中 | ✓ |
| 7 | `minConfidence=0`（无法计算） | 不误判为低置信 | ✓ |
| 8 | 50 次连续低置信 | 只换 3 次，不无限循环 | ✓ |

> 测试中抓到并修复了一个**真实缺陷**：`best` 原本与 `res` 比较，当轮次置信忽高忽低（0.80→0.60→0.75）时会被中间的低值覆盖，最终丢掉真正最高的 0.80。改为与自身比较后修复。

## §2 重构方向：可执行方案（**脚本已就绪，但实测揭示路径限制**）

### 2.1 已经做好的工具

| 脚本 | 作用 | 状态 |
|---|---|---|

| `analysis/train_refactor.py eval` | 固定划分评估 + McNemar | ✅ 已跑通 |

### 2.2 定向采样：配额表已生成

实测缺口（当前 220 张）：

```
5 组高危混淆对现状:
  混淆对      真值总次数   在第4位   误判目标次数   缺口
  x -> o         44         11          40        49
  c -> o         32         12          40        48
  y -> u         47          8          37        52
  w -> g         36         13          39        47
  g -> z         39          8          34        52

8 个高危字符（c,g,o,u,w,x,y,z）要在第 4 位各达到 60 例，还需补约 171 个字符位
（约 38 张验证码即可覆盖 —— 成本比想象的低）
```

**2000 张目标配额表**（`vm_dump/sampling_plan.json`）：

```
基础配额: 每字符 346 次
加权配额: 8 个高危字符额外 +173 次（共 519 次）
例如: c 现 32 → 目标 519（需补 487）；x 现 44 → 目标 519（需补 475）
```

**采集指引**：优先补真值含 `c/g/o/u/w/x/y/z` 的样本，且**刻意让它们出现在第 4 位**。

### 2.3 ⚠ 关键实测发现：**"冻结特征上换头"这条路走不通**

`train_refactor.py train` 已跑通，但结果给出了一个必须正视的结论：

```
位置     原生头      新架构(宽128+隐层64+Dropout0.2+增广)
 位1:   100.00%      63.00%     改进0  退化37  p=0.000
 位2:   100.00%      68.00%     改进0  退化32  p=0.000
 位3:   100.00%      58.00%     改进0  退化42  p=0.000
 位4:    98.00%      70.00%     改进0  退化28  p=0.000
 位5:   100.00%      30.43%     改进0  退化32  p=0.000
平均:   99.60% -> 57.89%   (-41.71pp)
```

**所有位置、各种超参组合都大幅劣于原生头。这不是脚本 bug，而是结构性问题：**

> **原生头是与 backbone 端到端联合优化的。冻结 64 维特征后，新头学到的只是"这个特征空间里如何拟合当前 220 个样本"—— 而该特征空间本身就是为旧头定制的、且已被证明"过度专属"（跨集迁移仅 32~74%）。换头无法绕过这个限制。**

**因此重构必须端到端重训**，不能只在特征上换头。这一条推翻了我此前"方案 C 改动最小"的乐观估计。

### 2.4 修正后的重构路线

```
第 1 步  定向采样（targeted_sampling.py 的配额表）
         目标：先把 8 个高危字符在第 4 位各补到 60 例（约 38 张，成本低）
         验收：采集后重跑 held-out 评估，第 4 位错误数应下降

第 2 步  端到端重训（必须，不能只换头）
         架构改动：
           * 全局向量 64 -> 128 或 256
           * 每个头 Gemm(64->26) -> Gemm->ReLU->Gemm
           * 加 Dropout / 权重衰减
           * 像素级增广（平移/缩放/弹性形变）—— 注意在**像素**空间做，
             不是特征空间（train_refactor 里的 aug 只是权宜之计）
         验收：在**固定留出集**上对比，McNemar p < 0.05 才算真提升

第 3 步  回归整条链路
         重新导出 ONNX -> 用 remove_initializer_from_input 清理结构
         -> 更新脚本/扩展内的模型 -> 跑一致性校验 + 行为测试
```

### 2.5 验收标准与止损线

| 指标 | 现状 | 目标 | 止损线 |
|---|---|---|---|
| 留出集整体准确率 | 98.00% | ≥ 98.5% | < 98.0% 则回滚 |
| 第 4 位准确率 | 98.00% | ≥ 99.0% | < 98.0% 则回滚 |
| McNemar p 值 | — | < 0.05 | ≥ 0.05 视为无提升 |
| 自动换图重试的额外成本 | 0 | ≤ 1 次/图 | > 2 次/图 则关掉重试 |

### 2.6 诚实的风险提示

1. **物理上限**：48.6% 的笔画只有 1~2px 宽 —— 这是字体渲染的物理下限，任何架构都受此约束。**重构的乐观天花板是 98.5%~99.0%，不是 100%。**
2. **收益量级小**：从 97.7% 到 98.x% 只有约 1 个百分点，而代价是重新采集 + 重训 + 全链路回归。
3. **交付物不同步风险**：新模型必须同时更新油猴脚本、扩展 `assets/`、以及 `install` 时的本地缓存键（`jaccount-captcha-nn-v1`），漏掉任一处会出现"两版行为不同"。
4. **不建议的方向**（均已实测否证）：改灰度输入（43.64% < 55.91%）、纯加宽向量（加剧过拟合）、CTC 序列解码（长度判定已零错误）、冻结特征换头（-41.71pp）。

## §3 两条线的协同关系

```
现成解（已完成）                     重构（进行中）
─────────────────                  ─────────────────
低置信 0.999                       定向采样配额表 ← 已生成
+ 自动换图重试 3 次                端到端重训 ← 待采样后启动
= 自动化 84.5%，正确率 100%        物理上限约 98.5%~99.0%
         │                                  │
         └────────────┬─────────────────────┘
                      ▼
              两者不冲突，可叠加：
              新模型提升"一次命中率"，
              换图重试兜住剩余的低置信样本
```

**协同要点**：重构提升的是"首次识别就高置信的概率"（当前 84.5%）。新模型若把该比例提到 90%+，那么"换图重试"的触发频率随之下降 —— 两者是互补而非替代关系。
