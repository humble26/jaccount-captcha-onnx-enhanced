# 识别模型优化空间评估报告

> 数据基础：220 张标注样本（`ground_truth_all.json`），其中调参集 120 张、留出集 100 张（两部分合并统计）。
> 模型：`nn_model.onnx`（ResNet-20，1.13 MB，输入 `[1,1,40,110]`，5 个输出头）
> 基线：`holdout_eval.json` 的 `pred.base` = **215/220 = 97.73%**

---

## 一、结论速览

**有空间，但空间已经被压到极限，且靶点极其明确 —— 只在一个位置。**

| 判断 | 证据 |
|---|---|
| 全部 5 个错误**都发生在第 4 个字符槽** | 第 1/2/3 位各 220 张零错；第 5 位 107 张零错 |
| 第 4 个输出头 `221` 是**系统性最弱的一环** | 最低置信 84.39%，其他头 96.98%~99.38% |
| 错误**全部是视觉近邻混淆** | `x→o`、`c→o`、`y→u`、`w→g`、`g→z` |
| 不是"字太糊" | 第 4 位笔画密度：错误样本 14.0% < 正确样本 16.5% |
| 不是预处理问题 | 11 种预处理变体 + 投票，净收益恒为 **0** |
| 不是优化器问题 | ORT 四个优化等级（DISABLE_ALL → ALL）预测完全一致 |
| TTA 已试过，**是负收益** | base 215 → tta1x3 / tta3x3 均 214（改进 0、退化 1） |
| 真值字符**从未掉出 top-3** | 987 位中 982 位 top1、3 位 top2、2 位 top3 |

## 四、为什么修不动：天花板判定

### 4.1 真值字符的排位分布（987 个字符位）

```
真值排第 1 名:  982 位 (99.49%)
真值排第 2 名:    3 位 ( 0.30%)
真值排第 3 名:    2 位 ( 0.20%)
真值排第 4 名及以后: 0 位 (0.000%)
```

**没有任何一个真值字符掉出 top-3。**

### 4.2 但"在 top-3 内"不等于"可重排"

关键数据 —— 第 4 位真值 logit 与 top1 logit 的差距：

```
正确样本 (n=215) 差距: 均值 0.000  最大 0.000     ← 真值就是 top1
错误样本 (n=5)   差距: 均值 4.472  最小 1.691
分界点: 正确样本最大差距 0.00  vs  错误样本最小差距 1.69
```

两者之间有 **1.69 的绝对间隔**，完全线性可分。这意味着：

* 任何**只依赖当前 logit / 置信度**的重排序或阈值策略，都不可能把它翻回来 —— 5 个错误的 top1 置信度分别是 99.58%、96.12%、99.45%、84.39%、97.07%，多数是"自信地错"。
* 用"低置信转人工"能拦住多少？（阈值实验）

```
阈值   90.0%  ->  转人工   1/220 (  0.5%)  自动通过 219 张准确率  98.17%  错误拦截 1/5
阈值   95.0%  ->  转人工   2/220 (  0.9%)  自动通过 218 张准确率  98.17%  错误拦截 1/5
阈值   98.0%  ->  转人工   6/220 (  2.7%)  自动通过 214 张准确率  99.07%  错误拦截 3/5
阈值   99.0%  ->  转人工   7/220 (  3.2%)  自动通过 213 张准确率  99.06%  错误拦截 3/5
阈值   99.5%  ->  转人工   9/220 (  4.1%)  自动通过 211 张准确率  99.53%  错误拦截 4/5
阈值   99.9%  ->  转人工  34/220 ( 15.5%)  自动通过 186 张准确率 100.00%  错误拦截 5/5
```

### 4.3 类内可分性测试

用 logit 做最近类中心分类器，第 4 位准确率仍是 **97.73%** —— 与直接 argmax 完全相同。说明**第 4 头的输出空间里，这 5 个样本已经贴到了错误的类别中心上**，没有留下任何可被后处理利用的余量。

### 4.4 混淆对的样本量

```
x->o  真值 x 出现 11 次, 误判目标 o 出现 9 次
c->o  真值 c 出现 12 次, 误判目标 o 出现 9 次
y->u  真值 y 出现 8 次, 误判目标 u 出现 12 次
w->g  真值 w 出现 13 次, 误判目标 g 出现 8 次
g->z  真值 g 出现 8 次, 误判目标 z 出现 3 次
```

两个方向各有 8~13 个样本，**不是"某类样本太少导致学不到"**，而是这两类字形在 40×110 二值化后的表征空间中**本身就是重叠的**。

## 五、可行动的选项（按性价比排序）

### 选项 1 —— 低置信转人工/换图（**唯一低成本且有实效的选项**）

利用 jAccount 验证码本身支持点击换一张的特性：

| 阈值 | 自动化率 | 自动部分准确率 | 错误拦截 |
|---|---|---|---|
| 99.5% | 95.9% | 99.53% | 4/5 |
| **99.9%** | **84.5%** | **100.00%** | **5/5** |

**99.9% 阈值下：84.5% 的请求全自动且 100% 正确，剩下 15.5% 直接触发"换一张重试"。**
按一次换图后可再识别的概率算，整体成功率显著高于 97.73% 的一次通过率，且**永不提交错误答案**。

> 这是唯一能在**不重训模型**的前提下，把"实际可用成功率"推上去的路径。

### 选项 2 —— 清理 ONNX 结构（卫生问题，非精度问题）

```
python -m onnxruntime.tools.remove_initializer_from_input \
  --input nn_model.onnx --output nn_model_clean.onnx
```

* 预期收益：**准确率 0（已实测四个优化等级完全一致）**，仅可能缩短会话初始化时间、消除 W 级日志噪音。
* 成本：极低，但需回归验证输出一致性。

### 选项 3 —— 重训 / 微调（唯一能把 97.7% 推上去的路径）

需要满足的前提：

1. **采样必须刻意加权第 4 槽**，尤其是 `x/o`、`c/o`、`y/u`、`w/g`、`g/z` 这 5 组对照。
2. **不能只加数据量**：220 张里这两类各有 8~13 例却仍然混淆，说明是**表征能力/输入分辨率**的问题，不是样本数量问题。可考虑：
   * 提高输入分辨率（40×110 偏高太矮，纵向信息被压扁）
   * 加深/加宽网络，或给第 4 头单独加容量
   * 在损失上对第 4 槽加权
3. **预期收益有上限**：即使重训，考虑到这是**二值化后的低分辨率图像**，`x↔o`、`c↔o` 这类区分需要笔画端点细节，实际可达上限估计在 98.5%~99.5% 区间，很难到 100%。
4. **成本**：需重新采集标注至少数千张、重新训练调参、重新导出验证、回归整个油猴脚本/扩展链路。**投入产出比明显低于选项 1。**

---

## 六、最终建议

**当前模型的空间已经基本榨干，剩余 2.3% 是这份数据 + 这个架构的判别极限。**

1. **首要动作**：实现**选项 1（低置信转人工/换图）**。这是把"实际可用成功率"从 97.73% 推到接近 100% 的唯一低成本手段，且改动只在脚本层，不动模型。建议阈值取 **99.9%**（对应 84.5% 全自动、100% 正确）。
2. **顺手做**：执行**选项 2** 清理 ONNX 结构，消除警告、可能加快初始化。**不要期待精度提升**。
3. **不要做**：TTA（已实测负收益）、更激进的预处理变体（已实测净收益 0）、寄望"后处理重排序"（真值 logit 与 top1 有 1.69 的不可越间隔）。
4. **可选长线**：只有在愿意重新采集数千张并重新训练的前提下，才考虑选项 3。即便如此，预期天花板也只有 98.5%~99.5%。
